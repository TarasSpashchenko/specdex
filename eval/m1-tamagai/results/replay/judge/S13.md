## Answer A

The reaction contract is §3 of the PRD addendum. It defines one interface that both the on-device and server brains implement, and it answers intent open question #15.

- **Request:** the request carries the visit context (prompt card, vocabulary, interests, objects on screen, current wish, age band and Pip's last three reactions) plus the input. The input is audio on the server tier, or the on-device recognizer's transcript on the on-device tier. On the server tier, the envelope also carries the credential, the contract version and the first-turn-today marker.
- **Response:** the brain returns one schema-validated event with seven fields: `emotion`, `action`, `line`, `unsure`, `crisis`, `intent` and `proposed_word`. On the server tier, the envelope also carries `transcript`. There is deliberately no field for the child's emotion (FR-49).
- **Mechanism:** every runtime uses JSON-schema-constrained output, and native tool calls are not used.
- **Client validator:** it converts types, strips code fences and maps unknown output to a fallback reaction. It checks `transcript` and `crisis` before it validates the reaction. `crisis` is the first field the brain generates, so a truncated answer still carries it.
- **Limits:** the prompt budget is about 150 tokens for the card, about 1,500 input tokens per turn and at most 60 output tokens. The engine enforces hard limits, not the prompt.
- **Evaluation suite:** it covers contract tests on the three runtimes, the NFR-14 probe sets, the crisis and child-exaggeration sets, a prosody probe and latency on reference devices.

## Answer C

§3, **“The reaction contract,”** defines one interface for both brains, resolving intent open question #15; architecture confirms the details.

The **request** contains the prompt card, Pip’s vocabulary, interest catalog IDs, screen objects, current wish, age band, Pip’s three previous reactions, and either server-tier audio or an on-device transcript; server requests also carry the prompt-card version reference, credential, contract version, and first-turn-today marker.

The **response** is one schema-validated event with these fields, plus a server-added, never-persisted `transcript` outside the brain’s JSON so brain failures cannot hide it; there is no child-emotion field.

| Field | Type or values |
|---|---|
| `emotion` | Enum |
| `action` | Enum; optional target object ID |
| `line` | Optional text |
| `unsure` | Boolean |
| `crisis` | `none`, `self_harm`, `suicide`, `abuse`, `danger` |
| `intent` | `normal`, `out_of_scope`, `health_question`, `self_claim_question`, `affection`, `feeling_stated`, `teach`, `food_or_hazard` |
| `proposed_word` | Text for voice-teach |

**Output and validation:** use JSON-schema-constrained output through LiteRT-LM `ResponseFormat.json(schema)`, llama.cpp `response_format` or GBNF, and vLLM structured outputs, without native tool calls; the client converts types, strips code fences, maps unknown reactions to fallback, and checks transcript/crisis before reaction validation, with `crisis` generated first and unreadable or unknown values deferred to the phrase list.

**Limits:** approximately 150 prompt-card tokens, 1,500 input tokens per turn, and at most 60 output tokens; child/Pip names use device-filled placeholders, and the engine enforces every hard limit.

**Evaluation:** contract tests across all three runtimes, NFR-14 probe sets, crisis and child-exaggeration sets as text and audio, a prosody probe, and reference-device latency measurements.
